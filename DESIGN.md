# Архитектурные решения

## 1. Отмена устаревших запросов и защита от гонки (Race Condition)

В `SearchController` (`src/domain/SearchController.ts`) отмена устаревших сетевых запросов реализована через связку **`AbortController`** и **`AbortSignal.any`**, а не через простую булеву переменную или счётчик запросов («актуальный ли это ответ»).

### Как это устроено

1. **Мгновенная отмена при каждом вводе:** В методе `onEditText` сразу вызывается `this.cancel()`, который отменяет ожидающий таймер `this.debouncedFetch.cancel()` и немедленно вызывает `this.controller.abort()` для уже ушедшего в сеть запроса (не дожидаясь истечения следующего `debounce`).
2. **Изоляция контекста запроса через локальную переменную:** Внутри `executeSearch` создаётся локальный экземпляр `const currentAbortController = new AbortController()`, который сохраняется в `this.controller`. В блоке `.finally()` сброс состояния загрузки происходит только после сверки владельца (`if (this.controller === currentAbortController)`), чтобы отменённый старый запрос не выключил индикатор загрузки для нового активного запроса.
3. **Композиция сигналов отмены и таймаута:** Сигнал формируется через `AbortSignal.any([currentAbortController.signal, AbortSignal.timeout(this.timeout)])`, что позволяет разделять в блоке `.catch()` ручную отмену (`DOMException` с именем `AbortError`, которая молча игнорируется) и превышение времени ожидания ответа (`TimeoutError`, которая передаётся в UI через `onTimeoutError`).

### Почему не достаточно простого флага «актуальный ли ответ»

- **Экономия трафика и ресурсов браузера:** Простой флаг лишь игнорирует ответ после его получения, но браузер продолжает скачивать тело ответа, парсить JSON и удерживать сетевое соединение. `AbortController.abort()` прерывает запрос на уровне сетевого стека браузера.
- **Предотвращение гонки во время окна `debounce`:** Если пользователь изменил текст и ждёт истечения таймера задержки, предыдущий запрос уже мог уйти в сеть. Немедленный вызов `abort()` в `onEditText` гарантирует, что старый ответ не успеет прилететь и отрисоваться под новым введённым текстом.
- **Точное управление спиннером:** Сравнение ссылок `this.controller === currentAbortController` исключает ситуацию, когда позднее завершение отменённого промиса сбрасывает `onLoading(false)` во время выполнения нового запроса.

## 2. Обоснование задержки `debounce`

В конструкторе `SearchController` (`src/domain/SearchController.ts`) и утилите `debounce` (`src/domain/debounce.ts`) установлена задержка по умолчанию **`400 мс`** (в модульных тестах `tests/searchController.test.ts` используется `300 мс` для ускорения прогона таймеров).

### Почему выбрано значение 400 мс

- **Баланс между отзывчивостью и нагрузкой:** Средняя пауза между нажатиями клавиш при наборе текста составляет 150–250 мс. Пауза в 400 мс отсекает промежуточные символы во время набора слова, но воспринимается пользователем как мгновенная реакция интерфейса.

### Что произойдёт при крайних значениях

- **Если убрать задержку (`0 мс`):** На каждый введённый символ будет уходить отдельный HTTP-запрос (`"I"`, `"Is"`, `"Isr"`, `"Isra"`, `"Israе"`, `"Israel"`). Это создаст лишнюю нагрузку на API, увеличит расход трафика, вызовет постоянное мигание спиннера и повысит риск превышения лимитов запросов (Rate Limit).
- **Если сильно увеличить задержку (`1500–2000 мс`):** Интерфейс начнёт ощущаться «зависшим» — пользователь закончит ввод, но будет ждать 1.5–2 секунды до появления индикатора загрузки и первых результатов, что ухудшит пользовательский опыт (UX).

## 3. Асимптотическая сложность (Big O)

### `mapCountryResponse` (`src/domain/mapCountryResponse.ts`)

Функция принимает массив DTO-объектов `data: CountryDto[]` длины $N$ и преобразует каждый элемент в экземпляр `CountryCart`:

- **Временная сложность:** **$O(N \cdot L)$**, где $N$ — количество найденных стран, а $L$ — количество языков (`raw.languages`) у одной страны. Внутри `data.map(...)` для каждой страны выполняется проход по массиву языков `raw.languages?.map(...)`. Поскольку количество официальных языков в одной стране ограничено небольшой константой (обычно $L \le 15$), на практике сложность линейна — **$O(N)$**.
- **Пространственная сложность:** **$O(N \cdot L)$** (или **$O(N)$** с учётом ограниченности $L$) — выделяется новый массив из $N$ объектов `CountryCart`, каждый из которых хранит массив названий языков.

### `mapFullCartResponse` (`src/domain/mapFullCartResponse.ts`)

- **Временная и пространственная сложность:** **$O(N \cdot (L + C + B))$** (на практике **$O(N)$**), где $L$, $C$ и $B$ — массивы языков, валют и кодов граничащих стран (`borders`), имеющие небольшой конечный размер для каждой страны.

### Кэш и сохранение истории (`SearchController.ts` и `src/data/storage.ts`)

- **Доступ к истории в памяти (`this.history[query]`):** Временная сложность поиска и записи по ключу поискового запроса в объекте `SearchHistoryCache` составляет **$O(1)$** в среднем.
- **Повторный запрос того же текста (`query === this.lastCompletedQuery`):** Проверка дедупликации последнего выполненного запроса в `onEditText` выполняется за **$O(1)$** и предотвращает повторный сетевой запрос.
- **Сохранение в `localStorage` (`storage.setItem`):** Сериализация массива найденных карточек `JSON.stringify(value)` имеет временную сложность **$O(N)$** пропорционально размеру сохраняемого массива объектов `FullCart`.
- **Поиск карточки на детальной странице (`renderFullCart` в `src/ui/cart/cart.ts`):** Поиск выбранной страны по имени в массиве кэша через `cachedCarts.find(...)` выполняется за **$O(N)$**.

## 4. Применённые принципы чистого кода

- **Разделение ответственности (Separation of Concerns) и SRP:**
  - Сетевой слой (`src/domain/searchCountries.ts`) отвечает исключительно за формирование URL, выполнение `fetch` и преобразование HTTP-статуса `404` в пустой массив `[]`, а прочих кодов ошибок — в типизированное исключение `HttpError` (`src/data/HttpError.ts`).
  - Слой маппинга (`src/domain/mapCountryResponse.ts`, `src/domain/mapFullCartResponse.ts`) изолирует преобразование и форматирование сырых данных API (`CountryDto`) в доменные модели (`CountryCart`, `FullCart`), защищая UI от `undefined` и отсутствующих полей.
  - Контроллер поиска (`src/domain/SearchController.ts`) инкапсулирует состояние поиска, `debounce`, таймеры таймаута и отмену запросов, взаимодействуя с UI только через коллбэки (`onLoading`, `onResults`, `onEmpty`, `onHttpError`, `onTimeoutError`, `onNetworkError`).
  - Слой представления (`src/ui/utils.ts` — функции `createView` и `renderView`, `src/ui/createCountryCard.ts`, `src/ui/cart/cart.ts`) отвечает только за декларативное описание и рендеринг DOM-дерева.
- **Защитное программирование (Defensive Programming):**
  - В `searchCountries` (`src/domain/searchCountries.ts`) добавлена ранняя проверка `if (!trimmedQuery) return [];`, предотвращающая пустые сетевые запросы даже при вызове функции в обход контроллера.
  - В `mapFullCartResponse` (`src/domain/mapFullCartResponse.ts`) используются опциональные цепочки (`?.`), операторы нулевого слияния (`??`) и значения по умолчанию (`'—'`), чтобы корректно обрабатывать страны без столицы, границ или валют.
- **Изоляция хранилища (Namespace Isolation):**
  - Обёртка `src/data/storage.ts` (`getItem`, `setItem`, `removeItem`) инкапсулирует сериализацию JSON и изолирует ключи приложения в `localStorage` с помощью префикса пространства имён (`search-country:${key}`).
- **Покрытие модульными тестами:**
  - Бизнес-логика изолирована от DOM, что позволило покрыть её юнит-тестами в `tests/debounce.test.ts`, `tests/searchCountries.test.ts`, `tests/mapCountryResponse.test.ts` и `tests/searchController.test.ts`.
